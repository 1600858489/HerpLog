# HerpLog 前端重构设计

## 目标

将现有 React 静态原型改造成分层清晰、移动优先、可交互的 Mock 前端，用于验证爬宠记录工具的核心业务流程。前端暂不接入后端，刷新后恢复初始 Mock 数据。

产品目标保持不变：用户应能在 3～5 秒内记录一次宠物事件；首页只展示今天需要处理的事项；事件是所有历史数据的基础。

## 范围

本次实现包含：

- 移动端与 PC 端响应式应用壳层。
- 今日、快速记录、宠物、时间线、概览五个页面。
- Pet、Event、CareTask、Dashboard 的内存 Mock 数据与派生计算。
- 保存事件后各页面的实时联动。
- 组件库内置的表单校验、提示、弹层与确认反馈。

本次不包含：后端 API、持久化、登录、多设备同步、图片实际上传、完整 Care Plan 编辑、状态管理、日历与复杂趋势图。

## 技术与组件边界

- 保留 React 18、TypeScript、Vite。
- 新增 `antd-mobile` 承担手机端交互；保留 `antd` 承担 PC 端布局、桌面表单和数据展示。
- 使用组件库提供的 `TabBar`、`NavBar`、`List`、`Card`、`Form`、`Selector`、`Popup`、`ActionSheet`、`Toast`、`Dialog`、`Layout`、`Menu`、`Grid`、`Statistic` 等组件。
- 不手写按钮、卡片、导航、弹层、表单控件等基础视觉组件；业务组合组件仅负责数据映射和交互编排。
- 自定义 CSS 仅用于应用级响应式布局、内容宽度、间距和安全区，不能替代组件库的视觉与交互能力。

## 目录与职责

```text
src/
├── app/                 应用入口、导航、主题与桌面/移动应用壳层
├── pages/               五个页面的组装边界，不持有可变业务数据
├── entities/            Pet、Event、CareTask、Dashboard 的领域类型与展示映射
├── features/            今日待办、快速记录、宠物、时间线、概览的组合与交互
├── mocks/               初始数据、内存仓库、派生规则和仓库接口
├── shared/              格式化函数、常量、组件库适配及全局响应式样式
└── styles/              仅应用布局和断点样式
```

每个页面从 feature 组合视图；feature 只依赖 entities、mocks 与 shared；mocks 是唯一可变数据源。页面和展示组件不得直接修改 Mock 数据。

## 双端信息架构与布局

### 手机端（小于 768px）

- `NavBar` 显示当前页面标题及最必要操作。
- `TabBar` 固定在底部，包含：今日、记录、宠物、时间线、概览。
- 页面内容单列纵向滚动，底部留出 TabBar 与 `safe-area-inset-bottom` 空间。
- 记录页通过 `ActionSheet`、`Popup`、`Selector` 和内联 `Form` 完成选择与输入，避免在小屏上并排堆叠控件。
- 任务、宠物、时间线为触控友好的整行可点击 `List` 或 `Card` 项。

### 平板端（768px 至 991px）

- 保持移动端顶部和底部导航，避免在中等宽度出现拥挤的侧栏。
- 内容区放宽，统计与简单快捷动作可使用两列 `Grid`。

### PC 端（不小于 992px）

- 使用 `antd` 的 `Layout`、`Sider`、`Menu`、`Header` 与 `Content`。
- 左侧常驻导航替代移动 TabBar。
- 内容区最大宽度为 1120px；数据卡片和记录表单通过 antd 栅格排列。
- 所有页面保留单列阅读主线，不以宽屏为由堆叠不必要的信息。

### 响应式约束

- 支持 320px、390px、768px、1024px 与 1440px 宽度。
- 页面不产生横向滚动；导航不得遮挡最后一项内容；弹层和表单不得超出视口。
- 不通过复制两套业务页面实现双端布局：共享数据和业务流，仅按断点切换应用壳层与布局组件。

## 领域数据与内存仓库

### 领域实体

- `Pet`：档案信息、当前状态、最近体重与下一项护理摘要。
- `Event`：宠物 ID、类型、发生时间、内容、备注与异常标记。
- `CareTask`：根据宠物、最近事件与固定 Mock 规则推导出的今日待办，包含提醒级别。
- `DashboardSummary`：从事件集合计算的近 30 天记录数、喂食次数、体重变化与异常数。

事件类型为：喂食、体重、排泄、蜕皮、照片。初始 Mock 数据应覆盖至少三只宠物和上述所有事件类型。

### 仓库接口

内存仓库提供：读取宠物、读取事件、按宠物读取时间线、保存事件、读取今日待办、读取概览统计。保存事件是唯一写入口。

保存流程：

```text
表单提交
→ 业务 feature 生成 Event
→ Mock 仓库保存
→ 重新推导 Pet 摘要、CareTask、DashboardSummary
→ 所有订阅页面刷新
→ Toast 显示保存成功
```

刷新页面后，仓库重新从初始 Mock 数据创建，不保留浏览器本地状态。

## 页面行为

### 今日

- 展示当前需要处理的事项，不展示冗余统计。
- 每项包含宠物、动作、提醒等级与上次相关事件摘要。
- 点击待办进入记录页，预选对应宠物和事件类型。
- 保存相应事件后，已完成的待办从今日列表消失或按新规则更新。

### 快速记录

- 先选宠物与记录类型，再呈现相应的最小动作流。
- 喂食：吃了/拒食、食物、重量；沿用该宠物最近一次喂食默认值。
- 体重：输入克数；显示最近一次重量作为参考。
- 排泄：默认正常；异常时展示备注输入。
- 蜕皮：默认成功；异常时展示备注输入。
- 照片：本次只记录照片事件和备注，不实施上传。
- 保存后保留在记录页，显示继续记录的快捷入口；用户可以连续创建多个事件。

### 宠物

- 以列表展示宠物名称、物种、当前状态、最近体重和下一项护理。
- 点击宠物后，以组件库 `Popup` 或 `Drawer` 展示档案摘要与近期事件，不进入独立详情页。

### 时间线

- 事件按发生时间倒序显示。
- 支持全部宠物和单只宠物筛选。
- 每项展示事件图标、宠物、时间、主要内容和异常状态。
- 保存事件后自动出现在最顶部。

### 概览

- 显示近 30 天总体状态和少量关键数值：记录数、喂食次数、体重变化、异常数。
- 数值完全由内存事件推导，不单独维护重复状态。

## 规则

- 每只宠物使用固定 Mock 饲养规则推导喂食和称重待办。
- 提醒等级：未到时间为绿；进入推荐区间为黄；超过最大周期为红。
- 宠物处于冬化状态时不生成喂食待办。
- 异常事件指拒食、异常排泄、异常蜕皮；概览异常数按近 30 天异常事件计数。
- 记录时间默认当前时刻；Mock 初始时间以相对日期构造，确保在任意运行日期下仍产生可见的待办和统计。

## 错误与反馈

- 使用 Form 的内置规则阻止缺少必填字段的保存。
- 无宠物或筛选无结果时使用组件库 `Empty`。
- 保存成功使用 `Toast`；不创建不会发生的失败分支。
- 删除、重置等不在本次范围内。

## 验证

- 执行前端构建与 TypeScript 检查。
- 在浏览器验证：320px 和 390px 手机宽度、768px 平板、1024px 和 1440px 桌面宽度。
- 手动验证一次喂食、体重、排泄、蜕皮和照片记录；确认它们即时联动到时间线、今日、宠物摘要和概览。
- 验证冬化宠物不出现喂食待办、记录后的待办更新、空筛选显示 Empty、刷新后数据恢复初始值。
